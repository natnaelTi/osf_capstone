# Hackathon execution guide

## Demo thesis

Regulatory complexity becomes manageable when guidance is tied to a real transaction, backed by visible sources, and escalated selectively when evidence conflicts or interpretation carries material risk.

## Core demo story

1. A technology business records a foreign-client invoice for exported digital services.
2. The system identifies missing facts and confirms assumptions.
3. It retrieves applicable evidence from a bounded official corpus.
4. It presents obligations, deadlines, documents, and a practical checklist.
5. The user opens a citation and sees exact source context.
6. A conflicting or updated source triggers a visible hold and professional-review question.
7. The policy professional resolves the high-risk issue without reviewing every low-risk extraction.
8. The resolution changes the action plan and remains in the audit trail.

## Build sequence

1. Define the synthetic transaction and source corpus.
2. Implement source records and provenance.
3. Implement transaction intake and assumption confirmation.
4. Implement guidance and obligation objects.
5. Implement evidence viewing and citations.
6. Implement conflict/review state.
7. Implement source-change comparison.
8. Polish the complete demo path and test failure states.
9. Add the goods-export expansion preview only after the core story is stable.

## Suggested evidence objects

Source document, source version, extracted provision, transaction fact, assumption, applicability finding, obligation, deadline, recommended action, conflict, review request, professional resolution, and guidance snapshot.

## Judge-visible proof points

- citation traceability;
- change detection;
- conflict handling;
- selective human review;
- practical action output;
- expansion architecture for goods exports and multilingual delivery.

## Scope cuts when time is tight

Cut decorative marketing pages, goods-export interaction, multiple transaction variants, monitoring breadth, then advanced motion—in that order. Do not cut traceability, the action checklist, conflict/review behavior, or the working service-export scenario.
